## One source, one worked reference

Keep `inputs/<neutral>/`, its private source repository, its exact Goal and every existing human attempt unchanged. The recording helper copies only that unworked starter. Keep worked plans in `walkthroughs/<neutral>/`, outside recorded project roots. Each plan binds its source commit and exact Goal hash and includes:

- `walkthrough.md`: complete edit instructions, file contents or exact replacements, commands, observed checkpoints, prepared narration, save/stop sequence and concrete recovery.
- Separate phase patches where a test-before-repair or intermediate proof matters, plus `solution.patch` for the full reference change.
- `rehearse.py`: a reproducible verifier using only a disposable copy of the pinned source and offline dependencies.
- `verification.json`: observed local rehearsal evidence, with truthful source/recording boundaries.

The existing cloud workflow runs the verifier against its prepared source/cache snapshot and creates a separate proof for each plan. Every meaningful expected failure must be validated as a failure for the specified reason, followed by the same check succeeding after the planned repair. Verify preserved behavior and boundary cases rather than tests that merely repeat the implementation. Record platform and dependency versions and any material limits, including whether a container check is static rather than a Docker image build.

The worked-reference artifact and its checksum are separate from the unworked starter artifact. The administrative owner verifies its complete inventory, source/Goal identities and actual successful cloud run before installing it in `/Users/Shared/TaskWorkPlans/`. Installation preserves prior owned plans, refuses edited/unmanaged destinations and produces a durable receipt. References and exact Notion scripts are kept on a second device or printed during recording. Never place a patch, answer key, prewritten final tests or finished deliverable in captured input folders during setup.

## Recording from the plan

Use the task’s current exact lane-specific Goal and live requirements: approved Goal and real assignment for Odin, candidate Goal and internal runbook for Bootcamp. Keep Bootcamp external approval fields empty. A guided Bootcamp walkthrough is supported practice; it does not complete the separately preserved unaided Human Transfer Test. The starting workspace must contain the original broken input. During the recording, execute the reviewed edits and tests manually and describe the supplied reasons and actual results. Use File → Save All before each check. If an outcome differs, use the plan's specific recovery branch instead of claiming the reference outcome happened. Save and inspect actual outputs, stop recording, and wait for Stopping → Archiving → Idle.

The cloud reference proof, synced reference and document readiness remain preparation facts. They do not check actual admission, QA, submission, earnings or human understanding on the user's behalf. Keep those fields pending until their real evidence exists.
