# Morning preparation

The existing Make owners generate ideas, prepare specs, hand cloud builds to Codex, publish operator packs, map skills and transfer reviewed attempts. The preparation workflow builds pinned starter/dependency kits and verifies complete worked references. `TaskWorkMorning.py` only synchronizes successful artifacts from that existing workflow; it creates no ideas, issues, worlds, repositories, practice attempts or builds.

The local preparation account owns one LaunchAgent, `com.taskwork.morning-refresh`, at 7:30 AM Monday–Friday and at login. It checks the current `ci/cloud-preparation` head and requires a successful build of that exact head. A matching installed kit is verified and reused without download, extraction, a rebuild or a task rehearsal. A pending or failed new build preserves the last verified kit. Both incoming archives are verified before installation; changed Shared inputs, metadata, references or owned outputs produce HOLD rather than overwrite. Original starter repositories and Recorder attempts are never sync destinations. Logs contain no authentication tokens.

The shared current surface is `/Users/Shared/TaskWorkMorning/index.html`, with a machine-readable `status.json`, the installed run/commit and links to each exact Notion script, complete reference, handoff and portable review process. The older start guide and native snapshots are dated exports; use live Notion for actual attempt gates and the current runtime receipts for current artifact identity. The launcher uses the existing preparation account’s authorized GitHub session. It does not copy credentials into Shared or Recorder.

A Mac that is off or a preparation account that is logged out cannot run its LaunchAgent. Cloud Make continues independently; the previous verified shared kit stays readable offline in the other account. At the first real Recorder login, the saved Codex handoff verifies and performs selected account-owned setup off-screen. Authentication and macOS camera/screen permissions require the real account; no receipt claims these happened before they did. Fast user switching preserves a logged-in preparation session. A later change of task is incremental and preserves earlier human edits.

For a new task, reuse its canonical issue and existing source/manifest result. Register only a real published pinned starter and reviewed exact Goal/runbook. The cloud worker must return the machine-readable manifest or real PR expected by the existing pack owner; a chat task link or “done” reply does not establish an importable world. Unbuilt or unreviewed rows remain queued. Once a reviewed task is registered and the preparation branch has a successful artifact, the same morning sync installs its kit without rebuilding older worlds.

The same manifest owner can now retrieve a published private starter with its existing GitHub connection and verify the full bounded Git tree/blob inventory. Its source-only audit never changes a finalized script or human gate. The saved task-idea Codex process supplies a complete reviewed registration, recipe, route, worked reference and learning mapping before the existing workflow can build a new runnable world. Morning never treats a pointer or retrieval result alone as that complete payload.

The existing weekday workday remains 8 AM–4 PM Eastern, lunch 12–12:30 and protected evening shutdown/sleep anchors. Friday 12:45–1:45 PM reuses the existing practice hour for guided recording and review. The initial exception-propagation rep targets the actual Python gap; it does not replace the active SAA-C03 priority or claim AWS architecture practice. End the block with a preserved recording and one evidence-backed next verification. Setup is automated or handled off-screen, and unfinished practice does not become evening catch-up.

The user also authorized moving SAA study inside the workday. The existing series continue Monday 3:15–4 PM, Tuesday 1:45–2:30 PM, Wednesday 2:15–2:45 PM and Thursday 1:15–2 PM Eastern, with current date-specific shorter slots where fixed commitments consume the available gap. Existing interviews, other work, lunch and evening events remain in place. These are scheduled study opportunities, not completed practice or credited hours; consult the actual calendar for exceptions.

Manual recovery under the authorized preparation account uses the same owner:

```bash
/usr/local/bin/python3 /Users/Shared/TaskWorkRuntime/TaskWorkMorning.py
```

Use `--offline` only to verify the installed kit without a new cloud read. Neither mode marks real-account recording readiness, review completion, unaided transfer, mastery, external approval or payment.
