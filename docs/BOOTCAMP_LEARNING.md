## Evidence and the review loop

1. Follow the existing complete guided route and preserve the real archive/workspace. Actual preparation/privacy/account checks still must occur.
2. Use the existing recording-review bundle/protocol. Review must cite actual visible/audible observations and finite timestamps for any observed skill or practice miss. A code diff or reference proof alone cannot show what the person understood.
3. Distinguish guided execution, explanation quality and unassessed unaided transfer. Green tests can support the saved implementation for tested cases while the person's independent implementation skill remains unassessed.
4. Treat review feedback as a proposal. For a real repeated miss, reuse the relevant existing world and its explanation/test section for bounded guided remediation. Route a separately authorized changed, unaided verification to the existing exact Human Transfer Test / [Human Rebuild](https://app.notion.com/p/3b98621e0a7a81ed9f46fcf32f00ec7b) path. Never reset an existing edited attempt or copy a solution into the protected learner workspace.
5. Human judgment decides whether the evidence addresses the gap. No report automatically updates a score, exam readiness, mastery, approval or Transfer Synced. The existing transfer owner still needs its actual destination/write/readback contract; do not create a parallel score/transfer flow.

All current human skill observations are **unassessed**. That means no reviewed human attempt is present, not that every skill is deficient. Existing PCAP/CTFL/CPRE gap records keep their own evidence dates and granularity; a guided world neither erases those records nor manufactures a new diagnosis.

The optional `report.skillFeedback` import is proposal-only:

```json
{
  "skillId": "finally-propagation",
  "observationKind": "guided",
  "finding": "unassessed",
  "evidence": [],
  "remediationTask": "batch-command"
}
```

For observed/needs-practice findings, evidence instead contains real `timestampStart`, `timestampEnd` seconds, the recording `artifact`, and the actual visible/audible `observation`. Use the selected task's mapped skill ID; the remediation world must already practice it. The validator rejects unsupported skills, invented objective IDs, stale Goal/source/route bindings, human mastery/readiness claims, guided-to-unaided promotion and feedback without recording evidence. A model's proposal remains advisory, and no official assignment grading or paid acceptance is implied.
